# 发布准备与使用边界

## 已实现的通用安装流程

| 原有缺口 | 当前处理 |
| --- | --- |
| 需要手工建立环境和拼接本机路径 | `scripts/bootstrap.py` 创建独立环境并生成实际路径配置 |
| 只有 stdio 服务入口，缺少安装诊断 | 增加 `configure`、`doctor`、`check`；无参数仍启动原有服务 |
| 无法提前区分缺依赖、缺引擎和版本不匹配 | 检查实际导入、目录写权限、引擎文件与已验证哈希；返回分项结果 |
| 包测试使用当前机器已经安装的依赖 | 增加干净源码复制、全新虚拟环境、中文/空格路径和实际安装验证 |
| 下载者可能带入模型和本地运行库 | 保留源文件白名单、私有目录忽略规则、分发包检查与合成测试夹具 |
| SDK 大版本升级可能破坏原有接口 | 限制 MCP SDK v1，并将最低版本收紧到本项目验证的 1.30.0 |
| 不同 harness 配置结构和存储位置不一致 | 增加 14 种配置输出、客户端目录及逐配置 stdio 检查；见 [兼容说明](harness-compatibility.md) |
| 多实例查询会误判外部任务，单实例信号量无法保护同一 CAD 会话 | 任务所有权文件锁与只读观察；跨工作目录的原生会话锁 |
| 只有几何任务可取消，缺少任务总览 | 通用 `list_jobs`、所有者处理的 `cancel_job`、阶段/心跳/耗时 |
| 工具返回结构和权限缺少统一边界 | 全部工具的输出 schema、annotations、结构化错误和服务端策略检查 |
| 工程专项工具默认全部开放 | 默认 40 个工具，9 个实验组工具和 8 个旧别名显式启用 |
| 输入目录和源文档保存未区分 | 可选输入目录白名单，递归依赖检查，源文档写入独立开关 |

安装脚本不依赖 Git，因此 ZIP 解压后也能使用。CI 增加 Windows Python 3.12 的完整安装流程（含 geometry）；实际 CI 状态以发布仓库执行结果为准。

## 下载后仍需使用者准备

- Windows 与 Python，以及独立安装的 LucidShape/CATIA 和有效许可。
- 本机实际的 `lush.exe` 路径。
- 真实仿真所需 CAD、光线、材料、位置和评估条件。这些属于使用者工程，不应打包进 MCP 源码。
- 首次原生 `health_check` 和小场景验证。MCP 初始化成功、依赖导入成功都不证明物理仿真正确。

## 当前不可通过安装脚本消除的限制

光学扩展保留 LS2.0 引擎哈希校验，其他版本需要新增验证资料和兼容实现。新 `optical-scene/1` 已将区域、材料、光源和工况移为配置，旧 S9 约束仅保留在兼容层；支持范围见 [通用化说明](generalization.md)。新的通用组合尚未新增原生光学实测，不能表述为任意整灯模型都能直接计算。GPU 固定穿透吸收问题没有因打包而解决；对照接口仍须保留其不同物理模型标签。服务不出具 GB/ECE 合格结论或 C-NCAP 得分。

## 上传前

确认目标仓库与代码授权范围。当前仓库未声明开源许可证；安装流程完善不等于已完成开源授权。不要上传 `local-data`、商业软件安装包、原厂手册、个人客户端配置或真实工程数据。

仓库脚本会检查并构建源码，不创建 Git 提交、不设置远端、不推送。

任务管理与策略升级步骤见 [任务和权限](operations.md)。Actions 配置会保存通过检查的 wheel/sdist 作为构建产物，不会自动发布 PyPI 或创建 GitHub Release。14 种配置经过 SDK 启动验证，不等于逐客户端实机验证；当前缺少目标原生版本和客户端应用的新增实测证据。HTTP/OAuth、MCP 原生 Tasks、断点续算、每种原生物理对象的专用输出 schema 不在本版交付范围。
